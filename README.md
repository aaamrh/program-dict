# LangRef：Kotlin / Java / Rust 语法速查

粘贴一段代码，页面列出里面用到的语法，点开就是说明、示例，以及 TypeScript 和 Java/Kotlin 的对照写法。也可以直接搜关键字，或者按主题浏览。

## 使用

在线版：<https://aaamrh.github.io/program-dict/>

本地：`npm run build` 后双击 `dist/index.html`，不需要联网，也不需要服务器。

- **粘贴代码**：左边粘贴后自动识别。不需要完整的类或函数，几行也行。右上角可以手动指定语言。
- **点代码看语法**：识别后点击左边代码的任意位置，右边会展开那里的语法卡片。
- **搜索**：按 `/` 聚焦搜索框，输入 `?.`、`lazy`、`impl`、`继承` 等；按 `Esc` 清空。
- **没有卡片的名字**：项目里的类、库 API 会列在最后。点"复制提问"会生成一段带代码的问题，粘给 AI 即可。
- 带"可能是"标记的条目来自关键字兜底匹配，出现在没能解析通的代码里，不一定准确。

## 修改与重新生成

需要 Node.js。

```
npm install        # 第一次
npm test           # 自检：每张卡片的示例都要能被自己的规则识别，验收用例要识别出期望的卡片
npm run build      # 自检通过后生成 dist/index.html
```

## 目录

- `src/engine.js`：识别引擎（tree-sitter 解析 + 卡片匹配），浏览器和测试共用
- `src/cards/<语言>/NN.js`：卡片数据，一个分类一个文件，按文件名顺序加载
- `src/app.js`、`src/app.css`、`src/index.html`：页面
- `tests/cases-<语言>.cjs`：验收用例（真实代码片段，包括不完整的片段）
- `scripts/probe.cjs`：打印一段代码的语法树，写新规则前用：`node scripts/probe.cjs kotlin a.kt`（设环境变量 `ALL=1` 显示 `?.` 这类符号节点）
- `scripts/test.cjs`、`scripts/build.cjs`：自检、打包
- `.github/workflows/pages.yml`：推送到 main 后自动自检、打包并发布到 GitHub Pages；自检不通过就不发布

## 卡片字段

| 字段 | 说明 |
|---|---|
| `id` | 唯一 id，前缀 `kt-` / `java-` / `rs-` |
| `title` / `syntax` | 标题、写法 |
| `why` | 干啥用的（必填）：解决什么问题、什么时候用，一两句话，显示在最上面 |
| `example` | 用法演示（必填）：有定义、有调用、用 `// 输出：…` 标出运行效果。必须能触发这张卡片自己的规则（自检会检查） |
| `vs` | 对比（必填）：`['不用它的写法', '代码']` 或 `['val 和 var 的区别', '代码']`，用注释标出差异和会报错的行 |
| `desc` | 要点（可选），支持 `` `代码` ``、`**粗体**`、`- ` 开头的列表行 |
| `ts` | TypeScript 对照（必填）。TS 没有对应概念时写 `// TS 没有对应写法：…` 加最接近的替代 |
| `cmp` | 其他语言对照（可选）：`['Java', '代码']` |
| `pit` | 常见坑（可选） |
| `q` | tree-sitter 查询，`@hit` 标出要高亮的位置 |
| `api` | 名字列表：代码里调用或引用了这些名字就命中，用于标准库和常用 API。Rust 宏名带 `!` |
| `kw` | 兜底正则（可选），只在解析出错的区域里使用，结果标为"可能是" |
| `tags` | 搜索关键词 |
| `see` | 其他语言里对应概念的卡片 id |

## 识别原理与限制

1. 用 tree-sitter 把代码解析成语法树。代码不完整时，会依次尝试补括号、包进类或函数里再解析，取错误最少的结果。
2. 语法层：每张卡片的 `q` 查询匹配语法结构，比如继承、命名参数、`?.`。
3. API 层：从语法树里取出被调用、被引用的名字，查 `api` 词典。
4. 兜底层：仍然解析出错的区域按 `kw` 正则匹配。

只看文本，不知道别的文件和依赖库里有什么。所以"这个名字从哪来""是什么类型"这类问题回答不了，要靠 IDE 跳转。同名的自定义函数会被当成标准库函数。
